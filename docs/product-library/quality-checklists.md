# Контрольные списки качества

Статус: `Canonical`

Эти списки применяются перед завершением задачи. Они не заменяют соответствующие разделы библиотеки.

## Новый или изменённый экран

- [ ] Решение оценивается как интерфейс Android-приложения, а не самостоятельного веб-продукта.
- [ ] За три секунды понятно, что происходит и что делать дальше.
- [ ] На экране один главный вопрос или объект.
- [ ] Есть одно основное действие.
- [ ] Заголовки и длительность не дублируются.
- [ ] Кнопка описывает реальный результат действия.
- [ ] Видимы ожидаемые «Назад», отмена или выход.
- [ ] Основное действие не маскирует автоматический переход.
- [ ] Состояние выбора понятно без цвета.
- [ ] Интерактивные области подходят для мобильного экрана.
- [ ] Фокус, labels, screen reader и reduced motion учтены.
- [ ] Единая тёмная тема читаема на всех участках градиента; системные зоны не дают светлой вспышки.
- [ ] Если проверка выполнена только в браузере, отдельно отмечены нативные Android-сценарии, которые ещё требуют эмулятора или устройства.

## Новый или изменённый текст

- [ ] Текст короткий, конкретный и понятен без психологического жаргона.
- [ ] Он не диагностирует и не интерпретирует пользователя.
- [ ] Нет обещания спокойствия или обязательного улучшения.
- [ ] Нет оценки, стыда, приказа «соберись» или давления вернуться.
- [ ] «Не знаю» и отсутствие изменения остаются допустимыми.
- [ ] Пример показывает форму, а не внушает содержание.
- [ ] Телесная инструкция условна и имеет альтернативу.
- [ ] Техническое обещание соответствует реальному поведению.
- [ ] Термины используются последовательно.

## Новая или изменённая практика

- [ ] Тренируется один навык.
- [ ] Выбирается конкретный и не самый тяжёлый момент.
- [ ] На каждом шаге один вопрос.
- [ ] Есть текстовый и мысленный путь ответа.
- [ ] Пустой переход не выдаётся за выполненное внутреннее действие.
- [ ] Приложение не подставляет личный ответ за пользователя.
- [ ] Собственная фраза визуально важнее объяснения.
- [ ] Есть короткая пауза и признание нулевого результата.
- [ ] Следующий шаг безопасен, мал и зависит от пользователя.
- [ ] При реальной угрозе приоритет отдан безопасности и помощи.
- [ ] Финал не содержит серии, награды или призыва продолжить.
- [ ] Практику нельзя успешно пройти только кликами.

## Напоминание

- [ ] Функция выключена по умолчанию.
- [ ] Разрешение запрашивается после понятного действия.
- [ ] Заголовок сообщает смысл, а не только настроение.
- [ ] В сообщении одно доступное действие.
- [ ] Нет упоминания пропуска, долга или серии.
- [ ] Нет прямой телесной команды без выбора.
- [ ] Нет обещания результата.
- [ ] Нет ссылки на несуществующую функцию.
- [ ] На экране блокировки не раскрывается чувствительный контекст.
- [ ] Состояния «включено / запрещено / недоступно» описаны честно.

## Изменение хранения данных

- [ ] Понятно, какие данные собираются и зачем.
- [ ] Выбрано минимально необходимое хранение.
- [ ] Пользователь видит, сохраняется ли личный текст.
- [ ] Нет нового облачного или аналитического сбора без отдельного решения.
- [ ] Удаление и срок хранения определены, если данные перестают быть только локальными.
- [ ] Текст на экране и фактическое поведение совпадают.
- [ ] Чувствительные данные не попадают в уведомления, логи и аналитику без необходимости.

## Финальная AI-проверка

Перед ответом о готовности нейросеть должна:

1. Назвать затронутые канонические принципы.
2. Проверить точный сценарий, включая выход назад и пустые состояния.
3. Проверить единую тёмную тему, системные зоны и уменьшение движения, если менялся UI.
4. Проверить, что старый исторический сценарий не вернулся случайно.
5. Обновить библиотеку и журнал, если возникло новое долгосрочное решение.
6. Отделить реализованный факт от гипотезы, которую ещё нужно проверить на пользователях.
