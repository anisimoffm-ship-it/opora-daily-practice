# Сборка «Опоры» для iOS и Android

## Роль платформ

Целевой продукт — прототип Android-приложения. Нативное поведение Android является эталоном для дизайна, навигации, системных зон, клавиатуры, разрешений, уведомлений и доступности.

Веб-запуск сохраняется как упрощённый тестовый стенд: он позволяет быстрее проверять экраны, тексты, состояния и основные переходы без полной нативной сборки. Это не самостоятельная веб-версия продукта. Системные сценарии, которые браузер не воспроизводит, необходимо отдельно проверять в Android-эмуляторе или на устройстве.

Проект iOS остаётся доступным технически, но не является целевой платформой текущего прототипа и не задаёт его интерфейсные решения.

## Параметры приложения

- Имя: `Опора`
- Bundle ID / Application ID: `com.opora.mobile`
- Web assets: `out`
- Capacitor core, CLI, iOS и Android: `8.4.2`
- Минимальная iOS: `15.0`
- Минимальный Android: API 24
- Target / compile Android SDK: API 36

## Повторная сборка

После изменения web-кода:

```bash
npm ci
npm run mobile:sync
```

Команда `mobile:sync` запускает production-сборку Next.js и затем `cap sync`.

Если изменился исходник `assets/icon.png`, сначала обновите нативные ресурсы:

```bash
npm run mobile:assets
npm run mobile:sync
```

Быстрая копия web-сборки без обновления нативных зависимостей:

```bash
npm run mobile:copy
```

## Xcode

Требуются macOS, Xcode 26.0 или новее и iOS 15+.

1. Установите полный Xcode и один раз запустите его, чтобы принять лицензию и установить компоненты.
2. Если активны только Command Line Tools, переключите активный Xcode:

   ```bash
   sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
   ```

3. В корне проекта выполните:

   ```bash
   npm ci
   npm run mobile:sync
   npm run mobile:open:ios
   ```

4. В Xcode выберите схему `App` и симулятор или подключённое устройство.
5. Для физического устройства выберите свою Team в Signing & Capabilities локально в Xcode. Не передавайте и не сохраняйте пароли, сертификаты или профили в репозитории.
6. Нажмите Run. Для текущей конфигурации используется Swift Package Manager; CocoaPods не требуется.

Перед архивированием вручную проверьте `Version`, `Build`, Bundle Identifier и настройки подписи. Публикация и архивирование в текущую подготовку не входят.

## Android Studio

Требуются Android Studio Otter 2025.2.1 или новее, Android SDK 36 и JDK из комплекта Android Studio.

1. В корне проекта выполните:

   ```bash
   npm ci
   npm run mobile:sync
   npm run mobile:open:android
   ```

2. Дождитесь Gradle Sync.
3. Выберите физическое устройство или эмулятор API 24+. Для основной проверки рекомендуется API 36.
4. Запустите конфигурацию `app`.
5. Для локальной debug-сборки используйте:

   ```bash
   ./android/gradlew -p android assembleDebug
   ```

Файлы `*.jks`, `*.keystore` и `key.properties` исключены из Git. Создание и хранение ключей подписи остаётся локальной операцией владельца приложения.

## Разрешения и нативные функции

- `INTERNET` нужен WebView Capacitor.
- `POST_NOTIFICATIONS`, `RECEIVE_BOOT_COMPLETED` и `WAKE_LOCK` добавляются официальным Local Notifications для существующих утренних и вечерних напоминаний.
- Разрешение точных будильников не добавлено. На Android 12+ система может доставлять напоминания приблизительно, особенно в энергосберегающем режиме.
- App plugin перехватывает системную кнопку «Назад» только внутри ритуала и на вложенных маршрутах. На главном экране выход передаётся Android, чтобы сохранить системный predictive Back.
- Локальные данные исключены из Android Auto Backup и переноса между устройствами: идентификатор практики и история напоминаний остаются только на текущем устройстве.
- Edge-to-edge включён на всех поддерживаемых версиях Android; status bar, navigation bar, вырезы и клавиатура обрабатываются через системные insets.
- Камера, геолокация, контакты, микрофон, push-уведомления и аналитические SDK не подключены.

## Чек-лист тестирования на устройствах

- Холодный запуск показывает splash без растяжения и затем главный экран.
- Иконка корректно выглядит на iOS, обычном и круглом Android launcher.
- Контент не перекрывается Dynamic Island, вырезом, status bar и нижним gesture bar.
- Поворот экрана и возврат в портретный режим не перезагружают текущий шаг.
- Клавиатура не увеличивает страницу и не закрывает активное поле.
- Кнопка «Назад» внутри практики возвращает на предыдущий вопрос, затем на главный экран.
- Android Back на вложенном маршруте возвращает назад, а на главном экране закрывает приложение.
- Настройки уведомлений запрашивают разрешение только при включении или тестовой отправке.
- Утреннее и вечернее напоминания появляются после сворачивания и перезапуска устройства.
- Отказ в уведомлениях не блокирует остальные функции.
- Локальные данные сохраняются после закрытия и повторного запуска приложения.
- Размеры текста, VoiceOver/TalkBack, фокус и интерактивные области не меньше 44×44 pt на iOS и 48×48 dp на Android проверены вручную.
- Светлая и тёмная темы не дают вспышку противоположного фона при холодном запуске; системные иконки сохраняют контраст.
- На Android 13+ themed app icon использует монохромный знак, а status bar уведомлений показывает отдельную монохромную иконку.
- Ссылки и переходы работают без сети после первой установки сборки.

## Известные ограничения

- Данные хранятся локально в WebView и не синхронизируются между устройствами.
- Удаление приложения может удалить локальные данные.
- Точность времени уведомлений на Android зависит от режима энергосбережения; exact-alarm permission намеренно отсутствует.
- Нативная компиляция требует установленных Xcode/JDK/Android SDK; `cap sync` не заменяет сборку в IDE.
- Подпись, архивирование и публикация не настроены.
